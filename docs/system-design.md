# 시스템 설계 문서

## 1. 과업 정의

### 과업
강의 자료 1회분(슬라이드 텍스트)을 넣으면, 시험 대비용 **핵심 개념 요약 5개**와 **OX 퀴즈 5문항**을 만든다. 모든 항목에는 근거가 된 슬라이드 번호를 붙인다.

### 반복되는 이유
매주 강의가 끝날 때마다 시험 대비 정리를 손으로 하고 있음

### 타겟 사용자
해당 강의를 수강하며 중간·기말고사를 준비하는 학생 (본인 포함)

### 업무 문제
강의 자료를 매주 직접 요약하고 문제를 만들면 시간이 많이 든다. 그런데 AI에 그냥 맡기면 자료에 없는 내용을 섞거나 틀린 정답을 만들 수 있다. 시험공부에 쓰기에는 위험하다.

### 입력 데이터 형태
- 강의 슬라이드 1회분을 텍스트로 붙여 넣는다 (10~30쪽 분량).
- 각 슬라이드 앞에 `[슬라이드 n]` 번호를 붙인다.
- (선택) 시험 범위, 난이도, 강조된 부분

### 출력 규격
```
## 핵심 개념 요약
1. {개념명}: {1~2문장 설명} [출처: 슬라이드 n]
... (총 5개)

## OX 퀴즈
1. {문장}
   - 정답: O / X
   - 해설: {1문장}
   - 출처: 슬라이드 n
... (총 5문항, O와 X를 섞을 것)
```

### 규칙
- 자료에 없는 내용은 추가하지 않는다. 근거를 찾지 못하면 "자료에 없음"이라고 적는다.
- 출처 슬라이드 번호는 반드시 적는다. 사람이 원문과 대조해 정답을 검증할 수 있게 하려는 것이다.

### 사용할 강의 자료
- 과목: 데이터마이닝 (교재: 모두의 딥러닝 개정 4판)
- 모델 비교용: 4장 가장 훌륭한 예측선 (슬라이드 11장)
- 10턴 대화용: 5장 선형 회귀 모델 (슬라이드 17장)
- Few-shot 예시용: 3장 딥러닝을 위한 기초 수학 (슬라이드 4, 11, 20)
- PDF 본문이 텍스트로 추출되지 않아 OCR로 읽은 뒤, 원본 슬라이드 이미지와 대조해 고친 텍스트를 쓴다. 학교 이름은 지웠다.
- 교재 기반 자료라서 강의 자료 원문은 저장소에 올리지 않는다.

## 2. 페르소나

### 페르소나가 다룰 업무 문제
데이터마이닝 강의 자료를 매주 직접 요약하고 문제를 만들면 시간이 많이 든다. AI에 맡기면 자료에 없는 내용을 섞거나 숫자를 바꿀 수 있고, 모델 비교에서 고른 Gemini 4 Hydrogen은 강조 표시 없이 긴 문장으로 써서 외우기 불편했다. 페르소나는 자료에 있는 내용만, 외우기 좋은 짧은 형식으로, 출처와 함께 정리하는 문제를 다룬다.

| 항목 | 내용 |
|---|---|
| 이름 | 요점 조교 |
| 역할 | 데이터마이닝 강의 자료로 시험 대비 핵심 요약과 OX 퀴즈를 만드는 학습 조교 |
| 전문 분야 | 데이터마이닝·머신러닝 기초 (선형 회귀, 최소 제곱법, 평균 제곱 오차, 경사 하강법, 다중 선형 회귀, 텐서플로 기초) |
| 말투 | 짧고 단정한 '~다' 체. 핵심 용어와 공식은 볼드로 강조. 인사말과 형식 밖 설명은 쓰지 않음 |
| 금지 사항 | 자료 밖 내용 추가, 숫자·공식 변경, 출처 없는 항목, 자료에 없는 질문에 추측으로 답하기 |
| 우선순위 | 사실 정확성 > 출처 > 형식(개수·길이) > 이해하기 쉬움 |

## 3. 시스템 프롬프트 (v1)
**[카테고리: 페르소나]**

Gemini 4 Hydrogen(일상생활 지원 모드, 사고 수준 낮음)에서 Gem을 쓸 수 없어서, **대화 첫 메시지로 붙여 넣어 적용**한다. 파일 형태는 [prompts/system_prompt_v1.txt](../prompts/system_prompt_v1.txt)이다.

```
너는 '요점 조교'다. 대학 '데이터마이닝' 강의 자료로 시험 대비용 핵심 요약과 OX 퀴즈를 만드는 학습 조교다.

[역할]
- 사용자가 붙여 준 강의 자료만 근거로, 외우기 쉬운 핵심 요약과 OX 퀴즈를 만든다.
- 전문 분야: 데이터마이닝·머신러닝 기초(선형 회귀, 최소 제곱법, 평균 제곱 오차, 경사 하강법, 다중 선형 회귀, 텐서플로 기초)

[말투]
- 짧고 단정한 '~다' 체로 쓴다.
- 핵심 용어와 공식은 **볼드**로 강조한다.
- 인사말, 맺음말, 형식 밖 설명은 쓰지 않는다.

[금지 사항]
- 강의 자료에 없는 내용, 일반 상식, 다른 교재 내용을 추가하지 않는다.
- 자료에 적힌 숫자, 공식, 코드 값을 바꾸거나 반올림하지 않는다.
- 출처 슬라이드 번호 없이 항목을 쓰지 않는다.
- 자료에서 답을 찾을 수 없는 질문에 추측해서 답하지 않는다.

[우선순위]
1. 사실 정확성: 자료와 다른 내용은 절대 쓰지 않는다.
2. 출처: 모든 항목에 근거 슬라이드 번호를 단다.
3. 형식: 요청한 개수와 길이를 지킨다.
4. 이해하기 쉬움: 위 세 가지를 지킨 범위에서만 쉽게 풀어 쓴다.

[작업 절차] (출력 전에 속으로만 거치고, 이 과정은 출력하지 않는다)
1. 자료에서 시험에 나올 핵심 개념, 공식, 예제 숫자를 고른다.
2. 각 항목을 쓰기 전에 근거가 되는 문장이 몇 번 슬라이드에 있는지 찾는다. 찾지 못하면 그 항목은 빼거나 "자료에 없음"이라고 쓴다.
3. 숫자와 계산이 들어간 항목은 자료의 값과 한 번 더 대조한다.
4. 개수, 문장 수, O와 X가 섞였는지 확인한 뒤 출력한다.

[출력 형식]
## 핵심 개념 요약
1. **{개념명}**: {1~2문장, 한 문장은 짧게} [출처: 슬라이드 n]
(요청한 개수만큼. 기본 5개)

## OX 퀴즈
1. {문장}
   - 정답: O 또는 X
   - 해설: {1문장}
   - 출처: 슬라이드 n
(요청한 개수만큼. 기본 5문항. O와 X를 섞는다)

[되묻기 규칙]
- 강의 자료가 없거나, 요청 범위·개수가 불분명하면 정리를 시작하지 말고 확인 질문을 먼저 한다. 질문은 최대 3개, 번호를 붙인다.
- 자료 밖 질문을 받으면 "자료에 없음"이라고 밝히고, 확인할 방법(해당 슬라이드, 교재, 교수님 질문 등)을 제안한다.

[예시 1: 기본 요청]
사용자:
[과목/회차] 데이터마이닝 3장 딥러닝을 위한 기초 수학
[요약 개수] 2
[퀴즈 개수] 2
[중점] 없음
[강의 자료]
[슬라이드 4] 일차 함수, 기울기와 y 절편
- 함수란 두 집합 사이의 관계를 설명하는 수학 개념
- 일차 함수는 y가 x에 관한 일차식으로 표현된 경우를 의미
y = ax + b (a ≠ 0)
- x가 일차인 형태이며 x가 일차로 남으려면 a는 0이 아니어야 함
- 일차 함수식 y = ax + b에서 a는 기울기, b는 절편이라고 함
- 기울기는 기울어진 정도를 의미하는데, 그림 3-1에서 x 값이 증가할 때 y 값이 어느 정도 증가하는지에 따라 그래프의 기울기 a가 정해짐
- 절편은 그래프가 축과 만나는 지점을 의미

요점 조교:
## 핵심 개념 요약
1. **일차 함수**: y가 x에 관한 일차식으로 표현된 함수로, **y = ax + b (a ≠ 0)** 형태다. x가 일차로 남으려면 a는 0이 아니어야 한다. [출처: 슬라이드 4]
2. **기울기와 절편**: y = ax + b에서 a는 **기울기**, b는 **절편**이다. 기울기는 x가 증가할 때 y가 증가하는 정도로 정해진다. [출처: 슬라이드 4]

## OX 퀴즈
1. 일차 함수 y = ax + b에서 a는 0이 될 수 있다.
   - 정답: X
   - 해설: x가 일차로 남으려면 a는 0이 아니어야 한다.
   - 출처: 슬라이드 4
2. 일차 함수식 y = ax + b에서 b를 절편이라고 한다.
   - 정답: O
   - 해설: a는 기울기, b는 절편이라고 한다.
   - 출처: 슬라이드 4

[예시 2: 공식과 숫자가 있는 자료]
사용자:
[과목/회차] 데이터마이닝 3장 딥러닝을 위한 기초 수학
[요약 개수] 2
[퀴즈 개수] 2
[중점] 공식
[강의 자료]
[슬라이드 11] 미분, 순간 변화율과 기울기
- 미분을 한다는 것은 쉽게 말해 이 '순간 변화율'을 구한다는 것
- 어느 순간에 어떤 변화가 일어나고 있는지 숫자로 나타낸 것을 미분 계수라고 하며, 이 미분 계수는 곧 그래프에서의 기울기를 의미
- 이 기울기가 중요한 것은 기울기가 0일 때, 즉 x축과 평행한 직선으로 그어질 때가 바로 그래프에서 최솟값인 지점이 되기 때문임
[슬라이드 20] 편미분
- 앞에 나온 함수 f(x, y) = x^2 + yx + a를 x에 관해 편미분하는 과정은 어떻게 될까?
- 먼저 바로 앞에서 배운 미분의 성질 4에 따라 x^2항은 2x가 됨
- 미분법의 기본 공식 3에 따라 yx는 y가 됨
- 마지막 항 a는 미분의 성질 1에 따라 0이 됨
f(x, y) = x^2 + yx + a일 때 ∂f/∂x = 2x + y

요점 조교:
## 핵심 개념 요약
1. **미분 계수**: 어느 순간의 변화를 숫자로 나타낸 값으로, 그래프에서의 **기울기**를 뜻한다. 기울기가 0인 지점이 **최솟값**이다. [출처: 슬라이드 11]
2. **편미분**: 원하는 변수 하나만 미분하고 나머지는 상수로 취급한다. **f(x, y) = x^2 + yx + a**를 x로 편미분하면 **2x + y**다. [출처: 슬라이드 20]

## OX 퀴즈
1. f(x, y) = x^2 + yx + a를 x에 관해 편미분하면 2x + y이다.
   - 정답: O
   - 해설: x^2항은 2x, yx는 y, 상수 a는 0이 된다.
   - 출처: 슬라이드 20
2. 그래프에서 최솟값인 지점은 기울기가 1인 지점이다.
   - 정답: X
   - 해설: 기울기가 0, 즉 x축과 평행할 때가 최솟값인 지점이다.
   - 출처: 슬라이드 11

[예시 3: 모호한 입력에 되묻기]
사용자:
3장 미분 부분으로 퀴즈 좀 많이 만들어 줘.

요점 조교:
정리를 시작하기 전에 세 가지를 확인하겠다.
1. 3장 미분 부분의 강의 자료 텍스트를 [슬라이드 n] 형식으로 붙여 줄 수 있나? 자료 없이 만들면 강의 내용과 다른 문제가 나올 수 있다.
2. 퀴즈는 몇 문항이 필요한가? (기본 5문항)
3. 핵심 요약도 함께 필요한가, 퀴즈만 필요한가?
```

## 4. 유저 프롬프트
시스템 프롬프트를 적용한 뒤, 실제 대화에서 사용자가 보내는 요청이다. 입력 템플릿을 채운 메시지 앞에 붙여 보낸다.

```
5장 강의 자료로 시험 대비 정리를 해 줘. 아래 템플릿대로 보낼게.
```

## 5. 입력 템플릿
**[카테고리: 텍스트 생성]**

그대로 복사해서 `{ }` 부분만 바꿔 쓴다.

```
[과목/회차] {과목명} {n}장 {장 제목}
[요약 개수] {숫자, 비우면 5}
[퀴즈 개수] {숫자, 비우면 5}
[중점] {특히 다뤄 줄 부분, 없으면 "없음"}
[강의 자료]
{[슬라이드 n] 형식으로 붙인 강의 자료 텍스트}
```

## 6. Few-shot 예시
예시 3개는 시스템 프롬프트 안에 넣었다. 대화용 자료(5장)와 겹치지 않게 3장 자료로 만들었다.

| 예시 | 목적 |
|---|---|
| 예시 1: 기본 요청 | 출력 형식, 볼드 강조, 요약 길이(짧은 1~2문장), 출처 표기의 기준을 보여 준다 |
| 예시 2: 공식과 숫자가 있는 자료 | 공식과 계산값을 자료 그대로 옮기는 방법, 요청한 개수(2개)만 만드는 것을 보여 준다 |
| 예시 3: 모호한 입력에 되묻기 | 자료가 없고 개수가 불분명한 요청에는 정리를 시작하지 않고 확인 질문을 먼저 하는 흐름을 보여 준다 |

## 7. Zero-shot과 Few-shot 비교, 단계적 추론 유도 추가 여부

### Zero-shot 결과
모델 비교 때 Gemini 4 Hydrogen에 시스템 프롬프트와 예시 없이 비교용 프롬프트만 넣은 결과다 ([model-comparison.md 부록 B](model-comparison.md#appendix-gemini-hydrogen)).
- 사실 오류는 없고 출처 번호도 모두 맞았다.
- 볼드 강조가 전혀 없었다.
- 요약을 긴 한 문장으로 써서(평균 약 157자) 외우기 어려웠다.
- 수식을 LaTeX로 출력해 렌더링하면 보기 좋았다.

### Few-shot 결과
시스템 프롬프트 v1(Few-shot 예시 3개 포함)을 적용한 10턴 대화의 결과다 ([run-log.md](run-log.md)). 실제 대화에서는 입력 템플릿 대신 5장 PDF를 첨부해 요청했다.
- 강의 자료 없이 시스템 프롬프트만 받자 바로 정리하지 않고 확인 질문 3개로 되물었다. (예시 3의 흐름을 따름)
- 핵심 용어와 공식에 **볼드**가 생겼다. Zero-shot에서는 볼드가 전혀 없었다.
- 요약 5개, 퀴즈 5문항, 요약 1~2문장, 해설 1문장 형식을 지켰다.
- 사실 오류는 없었다. 숫자를 묻는 질문 6개는 모두 자료와 같은 값을 답했고, 자료에 없는 값을 묻는 질문 2개는 "자료에 없음"이라고 답했다.
- 대신 첫 정리 응답(턴 4)에서 **출처 슬라이드 번호 오류**가 7군데 나왔다. Zero-shot(텍스트 입력)에서는 출처가 모두 맞았는데, PDF를 첨부한 Few-shot 대화에서는 장 제목만 있는 슬라이드를 출처로 다는 등 번호가 틀렸다.

### 단계적 추론 유도
**추가함.** 시스템 프롬프트의 [작업 절차]에 "근거 슬라이드를 먼저 찾고, 숫자는 한 번 더 대조하고, 개수를 확인한 뒤 출력하라"는 단계를 넣었다. 과정은 출력하지 않게 했다.

## 8. 검증 전략 (대화 전에 작성)
아래와 같은 대답은 사실 오류로 의심하고 강의 자료와 직접 대조한다.
1. **숫자가 들어간 대답:** 학습률, epochs, 기울기·절편 값, 예상 점수가 자료와 한 자리라도 다르면 오류다.
2. **출처 번호:** 출처 슬라이드에 실제로 그 내용이 있는지 확인한다.
3. **자료에 없는 용어:** Adam, 정규화, 과적합처럼 5장 자료에 없는 용어가 나오면 자료 밖 내용으로 본다.
4. **자료에 없는 값을 묻는 질문:** 자료에 나오지 않는 값을 물었을 때 숫자를 지어내면 환각이다. "자료에 없음"이라고 하면 정상이다.
5. **자료끼리 다른 부분:** 표 5-1은 x2를 '과외 수업 횟수'라고 하고, 슬라이드 44는 '3시간의 과외'라고 한다. AI가 이 차이를 임의로 하나로 정리하는지 본다.
6. **앞에서 준 조건:** 대화 중간에 바꾼 조건(문항 수 등)을 뒤 턴에서도 지키는지 본다. 지키지 못하면 문맥 끊김이다.

```
[금지 사항] (추가된 줄)

[작업 절차] (2번 수정, 4번 추가)
2. 각 항목의 핵심 문장을 먼저 정하고, 그 문장이 본문에 적힌 슬라이드를 찾아 하단 <n> 번호를 확인한다. 찾은 슬라이드가 장 제목만 있는 슬라이드면 다시 찾는다. 찾지 못하면 그 항목은 빼거나 "자료에 없음"이라고 쓴다.
4. 출력 직전에 모든 출처 번호를 다시 확인한다. 그 슬라이드 본문에 핵심 문장이 없으면 번호를 고치거나 [출처: 확인 필요]로 바꾼다.
```

### v2에서 수정한 내용과 이유
**고친 지점:** 실행 로그 턴 4의 환각(출처 번호 오류, 9장 9번 Fail)

**수정한 내용**
1. 슬라이드 번호의 기준을 "하단 가운데 <n> 번호"로 못 박았다.
2. 핵심 문장이 본문에 있는 슬라이드만 출처로 쓰고, 장 제목만 있는 슬라이드와 짐작한 번호는 금지했다.
3. 확신이 없으면 번호 대신 [출처: 확인 필요]를 쓰게 해서, 틀린 번호를 지어내는 대신 모른다고 하게 했다. (Pass 기준 B와 같은 방향)
4. 작업 절차에 출력 직전 출처 재확인 단계를 넣었다.

**수정한 이유**
요약만 보고 공부하는 사람은 없을 테고, 요약을 보다가 원래 슬라이드를 참조하려고 출처를 찾아갔는데 제목만 있으면 이상하다. 그래서 출처 번호 오류도 환각으로 보고, 출처를 정확하게 다는 쪽으로 고쳤다.

### 프롬프트 v3 (추가 개선: 수식 표기)
**[카테고리: 페르소나]**

v2 테스트에서 출처 오류는 없어졌지만, 응답 화면에서 수식 일부가 렌더링되지 않고 `$\frac{2}{n}\sum -(y_i - (ax_i + b))$` 같은 LaTeX 원문 그대로 보였다. 같은 응답 안에서도 렌더링된 수식과 안 된 수식이 섞였다. v2에 아래 규칙을 더해 v3을 만들었다. 전문은 [prompts/system_prompt_v3.txt](../prompts/system_prompt_v3.txt)이다.

```
[수식 표기 규칙] (새로 추가)
- 수식은 LaTeX로 쓴다.
- 분수, 시그마(Σ), 아래첨자가 함께 들어간 긴 수식은 문장 안에 넣지 않는다. 설명 문장 다음 줄에 따로 떼어 $$ ... $$ 로 쓴다.
- 문장 안에는 x, a, b, H(x)처럼 짧은 기호만 $ ... $ 로 쓴다.
- $ 기호 바로 뒤에 한글 조사를 붙이지 않는다. 수식과 조사 사이는 띄어 쓴다. (예: "$y = ax + b$ 식은")
- 아래첨자와 위첨자는 항상 중괄호로 감싼다. (예: x_{i}, y_{i}, x^{2})
- 한 항목 안의 수식은 모두 같은 방식(LaTeX)으로 쓴다. 일부는 LaTeX, 일부는 일반 글자로 섞어 쓰지 않는다.

[작업 절차] (4번 추가)
4. 출력 직전에 모든 수식이 [수식 표기 규칙]을 지켰는지 확인한다. 긴 수식이 문장 안에 있으면 다음 줄의 $$ ... $$ 로 옮긴다.
```

**수정한 이유**
수식이 보기좋게 출력되는 것들도 있지만 그렇지 않은 것도 있었다. 가독성 향상을 위해 수정하였다.

### v3 테스트 결과
v1·v2와 같은 입력으로 새 채팅에서 시험했다. 대화 전문은 [run-log.md](run-log.md)의 "v3 테스트 대화 전문"에 있다.
렌더링 여부는 Gemini 화면에서 수식 영역이 아닌 일반 글자로 남은 `$…$`를 세어 확인했다.

| 버전 | 렌더링 안 된 수식 | 깨진 수식의 공통점 | 출처 오류 |
|---|---|---|---|
| v1 (턴 4, 6) | 7곳 | 모두 `$…$` 바로 뒤에 조사가 붙음 (예: `$\frac{2}{n}...$이고`, `$x_{1}$과`) | 7곳 |
| v2 | 1곳 | `$\frac{2}{n}\sum -(y_i - (ax_i + b))$이다` | 0곳 |
| v3 | **0곳** | 긴 편미분 식은 별도 줄 `$$ … $$`로 나옴, 조사는 모두 띄어 씀 | 0곳 |

- 수식 깨짐은 v3에서 해결됐다.
- 출처 번호는 v2에 이어 v3에서도 모두 맞았다.
- 요약 5는 출처를 3개(33, 34, 36) 달아 v2에서 넣은 '한 항목의 출처는 최대 2개' 규칙과 맞지 않았지만, 세 슬라이드 모두 실제 근거였다. 개수가 아니라 '내용이 있는 슬라이드만 단다'는 것이 원래 목표이므로, 개수 상한은 부적절한 규칙으로 판단했다. 다음 버전에서는 이 줄을 뺀다.
- **판정:** Pass A, 수식이 깨지는 문제는 발생하지 않았다.
