# 미해결 기록

프롬프트를 고쳐도 끝내 원하는 결과를 얻지 못한 과업만 적는다. 성공한 시도는 적지 않는다.

## [미해결 1] 핵심 요약을 '짧게'와 '이해되게'를 동시에 만족하도록 만들기

### 원하는 결과
요약 한 항목이 외우기 좋을 만큼 짧으면서도, 자료 없이 읽어도 이해될 만큼의 부연설명이 들어간 결과

### 시도한 프롬프트 1: 모델 비교용 공통 프롬프트 (4개 모델에 같은 입력)
```
아래 [강의 자료]는 대학 '데이터마이닝' 과목 4장(가장 훌륭한 예측선) 슬라이드의 텍스트입니다.
이 자료만 사용해서 시험 대비용 정리 자료를 만들어 주세요.

[출력 형식]
## 핵심 개념 요약
1. {개념명}: {1~2문장 설명} [출처: 슬라이드 n]
(총 5개)

## OX 퀴즈
1. {문장}
   - 정답: O 또는 X
   - 해설: {1문장}
   - 출처: 슬라이드 n
(총 5문항, O와 X를 섞을 것)

[규칙]
- 강의 자료에 없는 내용은 추가하지 마세요. 근거를 찾을 수 없으면 "자료에 없음"이라고 적으세요.
- 모든 항목에 근거가 된 슬라이드 번호를 적으세요.
- 숫자와 공식은 자료에 적힌 값 그대로 사용하세요.

[강의 자료]
(강의자료 04의 슬라이드 11장 텍스트. 저작권 때문에 생략)
```

**받은 결과** ([model-comparison.md](model-comparison.md) 참고)
| 모델 | 요약 평균 길이 | 결과 |
|---|---|---|
| ChatGPT (GPT6) | 약 114자 | 짧지만 예제 숫자가 없고 설명이 부족함 |
| Gemini 4 Hydrogen | 약 157자 | 한 문장으로 길게 이어 붙임, 볼드 없음 |
| Gemini 4 Neon | 약 201자 | 부연설명은 많지만 너무 길어 외우기 어려움, 요약 4번은 개념 나열에 가까움 |
| Claude (Opus 5.5) | 약 152자 | 길이는 중간이지만 형식 밖 문장을 덧붙임 |

네 모델 모두 '1~2문장' 조건은 지켰지만, 문장 하나의 길이를 정하지 않아서 짧으면 설명이 부족하고, 설명이 충분하면 너무 길었다.

### 시도한 프롬프트 2: 시스템 프롬프트 v1의 말투·형식 규칙 (Gemini 4 Hydrogen)
```
[말투]
- 짧고 단정한 '~다' 체로 쓴다.
- 핵심 용어와 공식은 **볼드**로 강조한다.

[우선순위]
4. 이해하기 쉬움: 위 세 가지를 지킨 범위에서만 쉽게 풀어 쓴다.

[출력 형식]
1. **{개념명}**: {1~2문장, 한 문장은 짧게} [출처: 슬라이드 n]
```

**받은 결과** ([run-log.md](run-log.md) 턴 4, v2 테스트 턴 4)
- 볼드가 생겨 훑어보기는 쉬워졌다.
- '한 문장은 짧게'라고 했지만 수식이 들어간 요약(평균 제곱 오차 편미분)은 수식만으로 한 항목이 길어졌고, 부연설명이 없는 공식 나열이 됐다.
- 짧게 하라는 규칙과 쉽게 풀어 쓰라는 규칙 중 어느 쪽을 얼마나 지킬지 모델이 매번 다르게 정했다.

### 막힌 이유
- Neon은 1~2문장이긴 하지만 부연설명이 길어 이해하는데는 도움이 되지만 외우기가 힘든 문제가 있다.
- 그 이외에 다른 모델들은 너무 많이 요약하여 외우기는 쉽지만 이해하기는 어렵다.
**->인간의 입장에서 이해하기 쉬우면서 외우기도 쉽도록 요약하는 것은 아직 AI도 해결하기 어려운 문제인 것 같다.**

## [미해결 2] 강의 자료 안에서 같은 변수를 다르게 부른 곳을 정확히 찾아내기

### 원하는 결과
5장 자료에서 같은 변수나 개념을 슬라이드마다 다르게 적은 곳을 원문 그대로 인용해 알려 주기. 시험 공부할 때 헷갈리는 표현을 미리 짚어 두려는 목적이다.
- 확인된 정답 예: 표 5-1(슬라이드 19)은 x2를 '과외 수업 횟수'라고 하고, 슬라이드 21·27·41·43은 '과외 시간'이라고 한다.

### 환경
Gemini 4 Hydrogen(사고 수준 낮음), 시스템 프롬프트 v3 적용, 5장 PDF를 첨부한 v3 테스트 채팅에 이어서 요청 ([run-log.md](run-log.md)의 v3 테스트 대화 턴 7~12)

### 시도한 프롬프트 1
```
5장 자료 안에서 같은 개념이나 같은 변수를 슬라이드마다 다르게 표현하거나 서로 맞지 않게 적은 곳이 있으면 찾아서 알려 줘. 슬라이드 번호와 원문 표현을 함께 적고, 없으면 없다고 해 줘.
```
**받은 결과**
- 목표였던 '과외 수업 횟수 vs 과외 시간' 불일치는 찾았다.
- 하지만 원본에 없는 코드 오탈자 4건을 지어냈다. 슬라이드 26, 29, 30의 `a1_diff`와 슬라이드 39의 `%.02f`는 원본에서 모두 정상인데, `a1_dii`, `a1_di ff`, `a1_ a1_diff`, `8.02f`처럼 틀리게 인용했다.
- 표 5-1을 `공부한 시간(x)`라고 인용했지만 원본은 `공부한 시간(x₁)`이다.
- 슬라이드가 직접 바꿔 부른다고 설명한 용어(가설 함수, 손실 함수)까지 불일치로 넣었다.

### 시도한 프롬프트 2
```
다시 해 줘. 이번에는 아래 규칙을 지켜 줘. 1) 슬라이드에 실제로 적힌 글자만 그대로 인용해. 원문을 옮길 때 한 글자도 바꾸지 마. 2) 슬라이드에서 직접 '이렇게 바꿔 부른다'고 설명한 용어 변경(예: 가설 함수, 손실 함수)은 불일치가 아니니 빼. 3) 코드 오탈자는 슬라이드 화면에서 확실히 보이는 경우만 적고, 조금이라도 불확실하면 '확인 필요'라고 표시해. 4) 같은 변수나 개념의 이름이 슬라이드마다 다른 경우를 가장 먼저 찾아 줘.
```
**받은 결과**
```
저는 텍스트 기반 AI이기 때문에 그것은 도와드릴 수가 없습니다.
```

### 시도한 프롬프트 3 ('화면' 표현을 'PDF 원문'으로 바꿔 다시 시도)
```
앞에서 첨부한 5장 PDF를 기준으로 다시 해 줘. 1) PDF에 실제로 적힌 글자만 그대로 인용하고, 원문을 옮길 때 한 글자도 바꾸지 마. 2) 슬라이드가 직접 '이렇게 바꿔 부른다'고 설명한 용어 변경(가설 함수, 손실 함수, 옵티마이저)은 불일치가 아니니 빼. 3) 코드 오탈자는 PDF 원문에서 확실한 경우만 적고, 조금이라도 불확실하면 '확인 필요'라고 표시해. 4) 같은 변수나 개념의 이름이 슬라이드마다 다른 경우를 가장 먼저 적어 줘.
```
**받은 결과**
```
그것을 도와드릴 수는 없습니다. 저는 언어 모델일 뿐이에요.
```

### 막힌 이유
- 정확한 이유는 알 수 없지만 언어 모델일 뿐이라며 요청을 거절하였다.
- 우선 오탈자가 나온 이유는 교안의 글자가 텍스트가 아닌 이미지로 저장되어 있기 때문에 AI가 글자를 잘 못 읽었을 수도 있다.
- 때문에 잘못 읽은 것과 원래 자료가 틀린 것을 구분하지 못하고 슬라이드의 오탈자라고 보고한 것으로 보인다.
- 불일치가 있으면 찾아달라는 요청에 어떻게든 답변을 하기위해 환각이 발생시켰다.
- 슬라이드 화면에서 확실히 보이는, 글자 그대로 인용의 표현을 이미지를 직접 판독하라는 요청으로 AI가 이해해 요청을 거절했을 수도 있음.
- 강의교안을 첨부하고 많은 턴이 지나 강의교안을 다시 참조하지 못해 요청을 거절했을 수도 있음.
